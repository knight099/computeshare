# ADR-011: Safe synthetic M2 flow and local contributor controls

Only the compiled-in, bounded `synthetic-hash-v1` workload can execute. Its input is a short public string plus an iteration count; it takes no paths, commands, images, credentials or network destinations. A separate trusted worker process must join a delegated cgroup v2 with CPU, memory, swap and process limits before receiving input. Without those controls, execution remains unavailable.

The contributor dashboard is served on loopback by the Go agent, so Stop does not depend on the company site or network. Host/origin and CSRF checks protect mutations. Sessions require fresh explicit sharing consent, have UTC and local boot-clock deadlines, never resume after reboot, and cancel local work immediately on Stop/expiry/disconnection.

For this initial vertical slice, the modular API performs FIFO matching and transactional leases when an available Go agent sends `WORK_REQUEST` over the authenticated outbound connection. Offers travel in the versioned ACK; agents explicitly accept/start/complete them. The database owns job/session/attempt state. Cost: a standalone Go scheduling service now proposes candidates via the authenticated API; PostgreSQL remains authoritative. Payments and accounting are excluded by the updated product scope. No exactly-once execution or credits are claimed.

CPU-only dedicated mode is supported. GPU, idle-only mode, arbitrary files/artifacts, workload network access, and requested controls that cannot be enforced are rejected rather than displayed as functioning features. Wider platform/power/thermal policy adapters remain explicit M2 work.

All compute mutations, cancellation, and expiry sweeps take one deployment-local PostgreSQL advisory transaction lock before any row locks. This closes inverted-lock deadlocks and deliberately trades throughput for simple ordering in the preview. Splitting/partitioning this lock is a later measured change, not an HA claim.

Schema 3 captures new job journal events into a PostgreSQL outbox in the same transaction. The API publisher leases ten rows at a time, commits before broker I/O, publishes into an operator-scoped file-backed JetStream stream, and marks rows delivered only after broker acknowledgement. Failed publication releases the lease; crashes recover after 60 seconds. Stable event IDs deduplicate replays within NATS's two-minute window. Delivery remains at least once: consumers must deduplicate outside that window and tolerate event reordering. Streams retain at most seven days / 64 MiB; PostgreSQL history remains authoritative. No pre-migration events are backfilled, and no accounting or scheduler-consumer behavior is implied.

Hash verification uses at most two short-lived Node worker threads, with a 32-item queue and ten-second admission deadline. New jobs store their expected public hash before the submission transaction; old active jobs compute their expected hash before taking compute locks. State, ownership, session and lease checks are repeated after the asynchronous work. Capacity exhaustion returns 503 instead of blocking the event loop.

Linux workers receive SIGKILL when their supervising agent dies. The spawning OS thread stays locked through Wait because Linux parent-death signals follow that thread. Startup cleanup only removes empty UUID-named job cgroups under the validated delegated cgroup v2 root; populated or unknown groups are preserved.

Schema 6 adds an immutable per-job attempt budget (default one, explicit maximum three) and next-eligible time. A single recovery function owns terminal/requeue decisions for worker failure, local session interruption and lease loss. Requeue waits one then two seconds; invalid output and company cancellation stay terminal. Both inline and external paths derive new epochs from durable attempt history and check backoff before reservation. The contributor Stop still terminates local work immediately and never starts another local session; permitted replacement work requires another device's live request or fresh sharing consent. This provides bounded at-least-once execution, not exactly-once execution or fraud-proof computation.
