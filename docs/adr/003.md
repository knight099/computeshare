# ADR-003: Leases and idempotent transitions

Status: accepted and implemented for bounded built-in CPU work.

## Decision

PostgreSQL transactions and increasing attempt epochs fence state changes. A separate authenticated Go scheduler proposes assignments; the API revalidates fresh local intent, consent, resources, deadlines and exclusive capacity before reserving work. A shared reservation function serves inline development and external scheduling. Offers arrive over the authenticated outbound agent connection.

A transactional outbox captures committed job events for at-least-once publication to operator-scoped NATS JetStream. Stable event IDs support deduplication; consumers must tolerate reordering and duplicates beyond the broker's deduplication window. NATS does not own scheduling state or dispatch work in this implementation.

Explicit per-job attempt budgets permit bounded retries with backoff. Terminal company cancellation and invalid output cannot requeue work. Unique job/attempt usage keys prevent duplicate successful usage records. No financial settlement exists.

## Consequences and current limitations

Exactly-once execution is not promised. Lost or interrupted attempts may have done partial work; new epochs reject their late results. Only the reviewed bounded built-in hash workload is currently enabled. The preview's global compute transaction lock limits throughput and requires benchmarking before a scale claim.
